## Product and audience

**What it is:** Perfect Playlist is a local CLI and importable Python package
for people and AI agents who need to build Spotify playlists from exact track
URIs. Search and Inspect help with discovery; Build writes the chosen ordered
TrackSequence and Verify compares what Spotify stored.

**What a visitor should believe:** The final playlist can preserve the exact
tracks, order, and duplicates that were deliberately chosen.

**Next action:** Install from PyPI. The label is **Install Perfect Playlist**.

**Art direction:** Technical drawing, used as an honest diagram language for a
technical product. Cool paper, ink, and the existing green accent. No stock or
AI-generated photography.

## Journey

1. Recognition: playlist intent can be clear while a generated result is not.
2. Tension: multiple interpretive handoffs can change track identity or order.
3. Turn: a durable TrackSequence records canonical Spotify track URIs.
4. Proof: compare the sequence with Spotify's ordered read-back, including
   duplicates.
5. Commitment: install a small tool that makes the final write deliberate.

## Feeling curve

1. Calm: a quiet title page holds one promise in large type.
2. Tension: the handoff chapter names how a chosen track or position can shift.
3. Clarity: the technical drawing shows an exact sequence arriving intact.
4. Focus: the live alignment lets the visitor expose the first changed URI.
5. Confidence: a count drawn from the actual sample confirms duplicates remain.
6. Resolve: a small colophon and one install link leave a complete next step.

## Grammar and fingerprint gate

**Grammar:** Chaptered editorial. The product needs a readable argument and a
real method, so printed chapters fit better than a continuous camera flight or
a marketing page that behaves like a fake app. The filmic one-shot loses
because this journey needs chapter stops, not one continuous camera path.
Continuous world loses because there is no literal geography. Live surface
loses because the product is a CLI, not a visitor-facing dashboard; one real
comparison demo is useful, but making the whole page behave like a fake app
would misrepresent it. Typographic poster loses because the product needs more
than a sentence to explain its method. Gallery loses because there is no catalog
to browse. Argument split loses because there are not two balanced sides.
Rhythmic cutlist loses because hard cuts do not suit the precise, deliberate
method.

**Fingerprint check:** The resolved registry contains no earlier rows, so this
first build has no collision to clear. The planned shape is distinct chapters,
a changing folio, a still title page, an interactive alignment as the longest
chapter, and a running-text install close.
